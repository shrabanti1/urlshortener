# Deploying to Render

Render routes HTTPS straight to your container. There is no nginx, so the app
runs in **standalone mode** and does the jobs nginx normally does.

| Job | Docker Compose | Render |
|---|---|---|
| TLS | nginx + certbot | Render (automatic) |
| Serve the web UI | nginx static files | app (`STANDALONE=true`) |
| Security headers | nginx `add_header` | app pre-sending advice |
| Rate limiting | nginx `limit_req` | app token buckets |
| Schema setup | postgres init scripts | app (`RUN_MIGRATIONS=true`) |
| Redis | container | Render Key Value (or none) |

All of this is already configured in `render.yaml`.

---

## Read this before you start

**Free Postgres is deleted 30 days after creation** (plus a 14-day grace
period). A portfolio link that dies in a month is worse than no link. The
Blueprint therefore specifies `basic-256mb`, which is paid.

**Free web services sleep after 15 minutes idle** and take ~1 minute to wake.
For a URL shortener that is a bad failure mode: the first person to click your
short link waits a minute for a redirect. The Blueprint uses `starter`.

If you want to try the free tier anyway, change both `plan:` lines in
`render.yaml` to `free`, and know that you are on a 30-day clock.

Rough cost as configured: a Starter web service plus Basic-256mb Postgres came
to about **$13/month** in mid-2026, before bandwidth. Key Value has a free tier,
which the Blueprint uses.

> For comparison, the same stack on a Hetzner VPS is about EUR 3.79/month and
> runs the compose file unchanged. See [`docs/HOSTING.md`](HOSTING.md).

## Deploy

**1. Push to GitHub** (Render deploys from a repo):

```bash
gh repo create urlshortener --public --source=. --remote=origin --push
```

Check the secrets did not go with it: `git ls-files | grep -c '^\.env$'` must
print `0`.

**2. Create the Blueprint**

Render dashboard → **New** → **Blueprint** → connect the repo → Render reads
`render.yaml` and shows three resources:

- `urlshortener` — the web service
- `urlshortener-db` — PostgreSQL
- `urlshortener-cache` — Key Value (Redis)

Click **Apply**. `JWT_SECRET` and `IP_HASH_SECRET` are generated by Render, so
there is nothing to paste.

The first build compiles Drogon from source and takes **20-40 minutes**. Later
deploys reuse Render's layer cache.

**3. Set `BASE_URL`**

`BASE_URL` is marked `sync: false`, so Render asks you for it. You will not know
the URL until the service exists, so:

1. Let the first deploy finish and note the URL, e.g.
   `https://urlshortener-abcd.onrender.com`
2. Service → **Environment** → set `BASE_URL` to exactly that
3. Save — Render redeploys

Skip this and the API still works, but `shortUrl` in responses points at
`localhost` and every link you hand out is wrong.

**4. Verify**

```bash
curl -sS https://YOUR-SERVICE.onrender.com/health     # {"status":"ok",...}
```

Then open the URL in a browser: web UI at `/`, API docs at `/docs/`.

## What runs where

```
Render TLS ──> container :$PORT
                 ├── /            web/index.html      (static)
                 ├── /docs/       Swagger UI + spec   (static)
                 ├── /api/*       controllers
                 ├── /{code}      redirect
                 └── /health      health check
                        │
                        ├── Render Postgres   (managed)
                        └── Render Key Value  (managed)
```

Migrations run at start-up, before the listener opens, so no request can arrive
against a half-built schema. Every statement is idempotent
(`CREATE ... IF NOT EXISTS`, plus a guarded sequence reset), so re-running on
every deploy is safe.

---

## Dropping Redis to save a service

The app degrades gracefully without a cache. Delete the `urlshortener-cache`
database and the four `REDIS_*` / `CACHE_ENABLED` variables, then set:

```yaml
- key: CACHE_ENABLED
  value: "false"
```

Redirects then cost ~2.7 ms instead of ~0.6 ms, served straight from Postgres.
For a portfolio project nobody will notice.

---

## Updating

```bash
git push
```

Render rebuilds and redeploys automatically. Migrations re-run harmlessly.

## Troubleshooting

**Build times out or runs out of memory** — Drogon is a large C++ build. Render's
free build machines are small; the Starter plan is more reliable. If it keeps
failing, build the image in GitHub Actions instead (`.github/workflows/publish.yml`
already does this) and point Render at the published image.

**`Refusing to start: JWT_SECRET ...`** — a `generateValue` variable did not get
created. Set it by hand: `openssl rand -hex 32`.

**Short links point at `localhost`** — `BASE_URL` is unset. See step 3.

**Health check fails but logs look fine** — Render probes `/health`, which does a
real `SELECT 1`. A failing probe means the database is unreachable, not that the
process is dead. Check the database's status and that `DB_*` are wired
`fromDatabase`.

**Everything is slow on the first request** — the service is on the free plan and
went to sleep. That is the tier working as designed, not a bug.
